# 文字规范的提取与归档

提取或更新文字规范时读取。字段可适配目标 JSON；以下约定说明需要保留的信息，不要求重构已有兼容结构。

## 先提取使用条件，再记录数值

按用途组织条目，例如正文、辅助信息、标题、重要金额或对比价格。只有来源有依据时，才细分端、界面类型、状态、字符类型和强调程度。相同字号可能服务不同用途，不按数值去重；同属数字也不自动使用同一字体或字重。

| 信息 | 记录要点 |
| --- | --- |
| 字体 | 原始名称、已核实的别名、使用对象和要求强度。规范名称与设计软件实际可用字体名分开，未核实的别名不能作为绑定身份 |
| 字重 | 字重及其作用对象、强调条件、允许范围与例外。混合文字按有意义的区间区分 |
| 字号 | 数值、单位、适用的设计基准，以及单值、可选集合或连续区间的关系 |
| 行高 | 百分比、固定值、区间或自动值的类型与单位，以及适用场景。需要时保留相对字号计算的依据 |
| 其他属性 | 字距、段距、截断或行数等只有被明确规定且有执行价值时才收录；缺失不补成默认规范 |
| 来源 | 直接定义该规则的文字、表格或样式节点。定义分散在多个节点时，保留能支撑完整规则的必要引用 |

要求、建议、允许和禁止影响执行，不能在归档时改成相同强度。示例上的字体、字号或行数若只用于画板展示，不能据此限制所有使用场景。文本层的绘制属性也可能只是承载说明的排版，而不是说明中定义的规范值。

## 保留数值之间的真实关系

不要仅凭 `≈`、斜杠或左右两列猜测关系；它们可能表示可选、换算或不同端的取值。按说明和用户确认确定含义，记录关系与选用条件，仍不明确的部分进入 `unresolved`。

本次试用中，用户已确认 `13pt≈14pt` 表示 13pt 或 14pt，根据界面需求选择，并优先向上取值。因此适合保存为允许值集合与较高值偏好，不应写成 13–14 的连续区间，也不应要求所有合规的 13pt 都升级成 14pt。这个解释仅用于已确认采用该记法的规范，其他来源仍需按其定义判断。

“可选值”和“推荐值”分别记录；偏好不能把另一个允许值变成违规。用途限定也随值保留，例如某种价格场景的字号不能无条件套给所有金额。

画板展示的字阶序列不一定穷尽各场景允许的字号。按完整的场景定义归档；除非来源明确声明是完整清单，否则不将展示序列变成唯一白名单。

## 设计基准与背景信息

规范如有基准宽度、单位或稿件倍率，记录其适用范围，供后续将规范值映射到实际设计稿。设备屏幕、导出倍率、设计倍率和软件数值的含义不同，不从一项直接推定其他项；未确认的单位映射保留待核实。

本次用户说明，“375 的递进”和 `1.072` 是从设备屏幕折算到常规一倍设计尺寸的推导背景。保留有助理解的来源说明即可，不生成“对所有稿件乘除 1.072”的执行规则。实际审核仍需识别目标稿件的设计基准。

上述两项解释来自本轮用户对 [文字规范画板](https://relay.jd.com/file/design?id=2115760006212096002&page_id=11%3A1&node_id=11%3A47) 的确认；换用其他规范时重新识别关系与背景。

精确比例与画板中的整数示例不一致时，分开保存比例规则与示例，不自行推导统一舍入方式。不同场景定义了不同的行高或范围时，保留限定，不能用常见单行配置覆盖正文段落。

## 区分规范与试用经验

来源明确规定的字体、字号等进入规范记录。为了便于字段替换而采用的布局办法、金额基线校准、图形保护等，属于稿件处理方法；除非来源确有定义，否则留在友好化 skill 或案例中，不伪装成规范画板的要求。

引用应能回查定义；仅引用某个外观相似的样例，无法支撑该通用规则。用户补充的解释附确认依据和适用范围，不伪造画板节点或修订号。后续来源改变时，更新本次涉及的记录、引用和未决项，不修改其他规范包。

## 交付核对

- 能按用途找到适用条目，并区分条件、偏好、要求强度和例外。
- 字号集合与范围没有混淆，单位与设计基准没有丢失，字体别名没有被当作已验证资源。
- 行高类型与单位明确，示例舍入没有覆盖比例规则，推导背景没有进入无条件执行逻辑。
- 用户已确认的解释已同步更新；仍缺证据的部分继续列为未决，不将缺值记成零、自动值或某个常用数值。
