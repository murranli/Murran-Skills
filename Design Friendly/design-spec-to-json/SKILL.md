# 设计规范转 JSON

将用户指定的规范整理成可独立读取的 JSON，让后续 Agent 能按用途找到适用规则、读取确定值，并定位来源。规范画板作为只读来源，任务范围由用户指定。

## 读取和判断

1. 确认文件、页面、画板和本次归档范围。用设计工具读取结构以定位文字、图层属性、样式和变量，再按信息的用途组织 JSON。画板的章节、排版和命名方式可辅助定位。只收录能支持判断、执行或核对的信息，省略纯装饰和重复示例。
2. 区分条目的语义和画板中的展示属性。用途、状态、适用范围、前提与例外来自说明或明确标识。可直接核验的数值从对应属性读取，连同单位和生效位置记录。画板里的字号、间距、色块、截图等若仅用于示意，将它们作为说明上下文。明确要求或建议时保留其语气，避免从示例反推通用规则。
3. 每条记录选能定位到该条规范的来源节点。颜色优先引用色块，同条目的邻近文字提供名称和用途。仅以文字定义的条目引用文字节点，并说明取值依据。其他主题选择直接定义该值或规则的节点。名称、数值或规则有冲突时，先按来源或用户明确确认的优先级处理，剩余冲突写入 `unresolved`。

## JSON 约定

- `source` 标明规范标题、主题键及可核实的文件、页面、画板标识和直达链接。源修订号存在且可核实时一并记录。
- `records` 保存可按用途检索的条目。使用 `id`、`label`、`usage` 和 `refs`，再按主题记录有意义的数值、单位或枚举。状态、模式、适用范围和例外影响执行时一并记录。即使数值相同，用途不同的条目仍各自保留。
- `rules` 保存跨条目适用的规范，例如选用优先级、使用条件和例外。沿用原规范的限定，并在适用时附章节或来源。`unresolved` 保存仍影响使用的缺值、歧义和冲突，写明受影响条目、现有证据和待核实内容。全部核实时用空数组。按需使用 `fields` 解释字段语义，使用 `rationale` 保存理解规则所需的设计依据。
- 有明确且可区分条目的规范变量名或样式名时，`id` 沿用完整名称，包括原大小写、空格与斜杠，并在 `fields` 中说明。缺少规范名或同一名称对应多条规则时，给条目分配稳定的本地检索键，已核实的原名另存为 `variable_name` 或 `style_name`。来源节点 ID 用来定位。工具提供可绑定的资源身份且任务需要时，单独记录已核验的资源信息。

## 色彩记录

沿用 `id`、`label`、`hex`、`alpha_percent`、`usage`、`refs`。`refs` 为单元素数组，填对应色块节点 ID，纯文字规范填对应说明节点 ID。

`hex` 用实际纯色填充或明确指定的纯色属性，统一为六位大写 HEX。标注与明确配对的规范色块冲突时，以色块属性为准，除非规范或用户已另行指定优先级。`alpha_percent` 为 0–100 的数字。分别检查填充或描边和图层自身的不透明度，核实共同影响时记录该规范色的有效不透明度。确认完全不透明写 `100`。来源只以文字定义时，取明确写出的值或已核实的色名映射。缺值记为 `null`，并在 `unresolved` 说明待核实之处。保持 HEX 与不透明度独立，执行字段省略 HSB，避免从截图取合成色或把预览容器的不透明度算进规范值。

## 文字记录

提取文字规范时，读取 [references/typography-extraction.md](references/typography-extraction.md)。按文字的用途、场景和适用条件组织字体、字重、字号与行高；保留可选值、偏好和例外。区分执行规则、示例属性和推导背景。画板中的公式、设备尺寸或示例行数，只有明确影响使用时才成为执行条件。

## 更新与交付

更新已有 JSON 时，核对新来源身份和本次范围，复核受影响条目与规则，保留仍准确且兼容的检索键与字段。同步更新相关来源引用和 `unresolved`，保留仍未解决的项。用户已明确澄清的歧义，同步修订条目和规则，并移出未决列表；将澄清依据留在来源说明中。数值或名称改变时保留足以解释变动的证据。

写入用户指定的位置前，解析 JSON 并核对覆盖范围、ID 是否可区分、引用是否可定位，以及关键值与用途是否一致。颜色逐条核验 HEX 和不透明度的类型与范围。文字核验单位、可选值关系、使用条件及行高类型，避免背景信息或示例覆盖执行规则。报告已归档的范围和仍需核实的条目。
