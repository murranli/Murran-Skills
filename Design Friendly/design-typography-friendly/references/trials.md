# 文字友好化试用案例

需要理解判断边界、复盘修订或增补规则时读取。案例值来自当时的规范与稿件，换档后以本轮 JSON 为准。表中的布局判断经验不等同于品牌规范。

## 规范解释与用途匹配

| 观察 | 判断与处理 | 验收或边界 |
| --- | --- | --- |
| 字号写为 `13pt≈14pt`，用户确认是“或”的关系并优先向上 | 保存为允许选项及选用偏好，结合实际界面选择；已有合规低档不因偏好而变成违规 | 不把两个允许值压成唯一值，不把近似号直接当容差计算 |
| 规范包含“375 的递进”和设备相关的 `1.072` 换算 | 这是设备到常规设计尺寸的背景解释；先确认稿件倍率，再比较规范值 | 不对已经是常规倍率的稿件重复换算，不将设备公式当通用字号表 |
| 商品标题、辅助说明、主价和营销展示标题位于同一页面 | 按用途分别匹配；列表金额保留适用的混合字号比例，未被规范明确覆盖的营销展示字号保留并说明 | 不将详情金额规格直接套用到列表，也不强行把特殊展示文字塞入普通标题档位 |

## 文案替换与布局

| 观察 | 判断与处理 | 验收或边界 |
| --- | --- | --- |
| 优惠券符号和主数字使用不同字号，容器底部对齐后符号显得下坠 | 以主数字为准，拆层金额改用基线对齐，并检查符号字形的实际位置 | 校验整数与小数、不同位数；不靠移动主数字迁就符号 |
| 原来单行的门槛说明被额外预留两行，券卡随之变高 | 移除没有依据的双行最低高度，恢复原有行数预算 | 不由“将来可能很长”推导新增行数；已有明确多行预留也不能仅因当前文案短而减掉 |
| 连续说明 `100京豆抵` 与金额拆成两层，前段填充剩余宽度 | 前段改为自然内容宽度，让金额紧接其后；剩余空间留在整句与图标之间 | 保持原单行、基线、字体格式及外部图标尺寸位置 |
| 同稿中“最高抵”与金额之间仍存在同类间隙 | 整稿复查找到前段宽 44、自然内容宽 33 的差异，改为自然宽，金额随之前移 | 检查全部同类入口，而非仅修截图中一处；文案和其他样式保持不变 |
| 主标题前段的自然宽与固定宽相同；`5` 后的“倍京豆膨胀”为左对齐末段填充 | 未发现内部多余间隙，保留原有宽度和截断边界 | 不把所有拆层文字统一改为 HUG；句尾空白本身不是错误 |
| 商品卡包含徽章与标题、两种服务权益、价格与价格说明 | 这些字段语义独立，保留原有有意间距；描述承担截断，关键金额保持完整 | 不因位于同一行就认定它们是连续语句 |
| 较长商品名、价格说明及 `¥799.9` 替换后需要适应 | 标题和说明保持原单行预算及末尾省略；金额区间继续保留不同字号，操作图标保持固定尺寸 | 核对所有重复卡片，包括列表后续内容；测试结束恢复原文案及格式 |

## 保护非文字造型

优惠券文字重排时，部分缺口变成椭圆或出现横缝。原因是布尔造型按容器宽度被横向缩放：内部圆形失去等比，构造边界又被误当作可见宽度。

保留布尔操作内部各形状的尺寸与相对关系，让文字变化只驱动必要的排布。构造用的减去圆形可以超出券卡可见边界，不能为了让布尔外框与卡宽一致而压缩它们。此案例修复后检查了全部重复券卡，并在文字高度变化的测试中验证圆形与可见宽度仍稳定。

上述结论适用于“文字修改不能意外改变图形造型”的边界判断，不要求所有图形一律使用固定尺寸；确需响应式变化时，应按组件原有行为处理并验证。
