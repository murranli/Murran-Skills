# 设计稿文字友好化

## 确定任务和规范来源

使用用户指定的稿件或明确选区，区分只审核、按规范校准和改善文案替换适应性。写入范围以本次任务为准；用户要求保留原稿或在右侧调整时，先建立可编辑副本。文字布局调整可以改变必要的文字容器和相关排布，不能据此重设计其他维度。

优先读取本轮指定的文字 JSON，其次使用项目明确配置的规范。换档后重读来源、字段说明、条目、规则和未决项，重新核实本次匹配；旧文件的字号、字体或判断不能直接沿用。规范缺失时可盘点文字和检查布局问题，依赖规范的结论标为待核实。

按含义映射 JSON 字段，不要求固定字段名。通常从 `source` 核实来源，按 `records` 中的用途、适用条件和数值查找规则，结合 `rules`、例外及 `unresolved` 判断。`refs` 用于必要时回查来源。区分已确定要求、允许选项、推荐偏好、示例和背景解释；缺值或冲突不能当作任意值或规范豁免。

## 按倍率和用途匹配规范

结合画板尺寸、来源说明、组件尺寸及实际属性判断设计倍率，再把规范值和稿件值换算到同一尺度比较。不要仅凭画板宽度猜倍率，也不要把特定设备到常规设计尺寸的背景换算重复应用到已经归一化的稿件。倍率不明且影响结论时，先核实这一项。

按文字的作用和场景匹配条目，例如标题、正文、辅助说明、强调或金额。节点名和当前字号是线索，不能取代用途判断；同值异用的条目仍分别匹配。规范没有覆盖的展示文案保留现有选择并说明依据，避免强行归入最接近的字号档位。

- 分别核对字体家族、版本、字重、字号、行高及规范明确要求的其他属性。具体数值以本轮 JSON 为准，不把某次项目的字体、字号或行高写成通用默认值。
- 允许多个值的条目按可选集合判断。规范中已确认的“优先向上”是选用偏好，不能据此把较低的允许值判为违规。既有值合规且满足界面需求时保留；需要选值或校正时，在满足布局与内容需求的候选中采用规范偏好。
- 读取整段富文本的实际区间，不用单个代表值覆盖混合字号、字体或字重。区分正文数字、强调数字、金额符号、主数字和小数等角色，沿用该场景适用的规范。
- 对应字体不可用时说明缺口，采用项目已确认的替代方案；不要悄悄替换为看似相近的字体。按设计工具当前文档加载实际需要的字体和设置属性。

## 让文案替换保持正确展示

设计稿中的示意文案不能代表字段长度的上限。先判断字段之间的语义关系和展示优先级，再配置容器、适应、对齐及截断。下面是布局判断经验；它们不应冒充 JSON 中已有的品牌规范。

### 连续文案按一个语义整体处理

同一句话或同一金额内部的字体、字号、颜色差异，不应引入额外空隙或拉伸。优先使用富文本保留格式；现有拆层结构能稳定表达同样逻辑时可保留。

确需拆层时，让各段按内容自然衔接，由整句承担与外部图标、按钮或其他字段之间的空间适配。检查固定宽、填充剩余宽度、两端分布、尾随空格等是否把连续内容推开；修复实际造成间隔的设置。

不要把所有文本批量改成自适应宽度。左对齐的末段填充宽度只在句尾留空时，可以继续承担截断；整句也仍需符合可用空间。徽章与标题、不同服务权益、价格与价格说明等独立信息可以保留有意的间距，不因同行展示就合并成一句。

### 保留已有行数预算

无明确证据时，不改变原稿对该字段预留的行数。依据原有容器、行数限制、组件状态和使用说明判断预算，不能用当前短文案实际占用的行数代替预留行数，也不能为了容纳假想的长文案统一新增两行最低高度。

有宽度边界的描述字段，在原有行数内配置适应与末尾截断；本来允许多行的字段保留相应换行逻辑。短按钮或标签可随内容增长到合理边界。优先保持关键内容完整、说明让出空间的关系，具体取舍仍由界面语义和规范决定。无法同时满足内容与边界时，明确冲突，避免暗中缩字、改文案或增加行数。

### 混合金额围绕主数字校准

以主数字为基准处理符号、整数和小数。单一富文本保留区间格式；拆层金额优先使用工具支持的基线对齐，再检查符号的实际视觉位置。容器底部对齐不等于字形基线对齐，也不能通过随意移动主数字去迁就符号。

校验不同位数及小数时，确认金额整体连续、关键数字完整、各区间格式仍正确，周围说明和操作控件按既定优先级适配。不要把价格与独立说明之间有意的间距当作金额内部间隙。

## 实施与整稿复查

先记录实际文字、区间格式、容器与对齐关系，再按用途修正。优先局部属性和实例覆盖，保留组件关系；只有原结构不能表达正确逻辑时才调整文字相关结构。

文字容器可以随规范行高和已确认的内容需求重新排布。图标、图片、布尔造型和装饰应保持尺寸、比例及形状；不要把它们随文字容器一起拉伸。布尔操作的构造边界可能超出可见造型，不能按表面宽度归一化其内部几何。核对排版变化是否意外影响缺口、圆形、圆角和裁切。

修复截图中的问题后，检查本次指定稿件内所有同类字段，覆盖重复卡片、富文本、组件实例和列表后续内容。根据组件状态判断隐藏备用层是否属于本次范围，不擅自显示、清理或重设其他状态。

验收同时看属性与渲染：

- 规范匹配、设计倍率、各富文本区间和允许选项是否正确；不能只看属性设置成功。
- 连续文案是否自然衔接，独立信息间距是否仍成立；基线、符号视觉位置和预留行数是否正确。
- 对本次调整所影响的字段，选少量有代表性的短、长文案或金额做替换检查，确认截断、关键内容和固定控件符合预期。使用可恢复的副本或测试状态，结束后恢复原文案及区间格式。
- 比较原稿与修订稿的非目标属性、图形几何、组件关系和实际呈现，解释必要的排布变化，修复意外变化。报告已检查范围、实际修改和影响交付的未决项。

## 随试用迭代

规范值的更新通过重新读取 JSON 生效。通用布局经验只有在试用中发现可复现的判断缺口时才修订，保留适用条件和反例，不将个别稿件的选择扩大成绝对要求。

需要复盘已验证案例或用户要求沉淀试用经验时，读取 [references/trials.md](references/trials.md)。用户要求更新规则时，将观察、证据、处理与验收结果沉淀到对应条款，并用相关旧案例复核。日常稿件修复不自动修改 skill、发布文件或推送仓库。
