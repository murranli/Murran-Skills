# 可视化对象提取

凡被选书页中出现表格、矩阵、统计图、流程图、地图、时间轴、截图、插图或其他可视化对象，均需阅读本文件。生成围栏 SVG 前还须阅读 `svg-reconstruction.zh.md`。

## 1. 选择范围

星号、箭头、对勾、圈、括号、侧边线或手写符号明确指向一个图表时，视为选中整个对象。剥离读者标记，纳入所有必要附属信息；图内标签无需逐个标注。

用户明确要求**全部图表**时，每张已提供照片中的所有可视化对象都被选中，即使没有标记；一页有多个对象也要分别识别。若用户声明“上传照片就意味着其中图表都要提取”，该规则在当前书籍会话持续生效，直到用户修改。扩展范围只适用于图表，普通正文仍按物理标注处理。

标记可能同时指向正文和图表时，根据方向、距离和包围关系判断；仍无法确定则报告歧义，不得静默选择。

## 2. 图表语义单元

以下内容组成一个单元：

1. **图表本体：** 单元格、节点、连线、分组、坐标轴、尺度、编码形状和可读数值。
2. **必要附属：** 图号/表号、标题/图注、图例、单位、来源、脚注、标注线及图表内印刷注释。
3. **结构化转录：** 可搜索的行列、节点、关系、层级、方向或印刷数据描述。
4. **直接关联说明：** 最少量、明确介绍或解码图表的邻近完整句，标为“关联说明：”。
5. **识别说明：** 具体不确定项、损坏、截断或证据缺失。

普通邻近论述不会因谈到图表就自动被选中。图表后若有独立标注正文，先写“其他独立标注：”。同时满足两类的句子只在“关联说明”中出现一次。

## 3. 默认保存形式

默认交付物是**单一 Markdown 文件，不含截图、图片链接或 Base64 数据**。通过结构化文字及必要时兼容 Obsidian SVG Editor 的 `svg` 围栏保存图表。每个 SVG 使用 `svg-reconstruction.zh.md` 规定的固定浅色画布与明确前景色，使笔记可搜索、可复制、体积可控，并在 Obsidian 不同视图和主题下保持清晰。

源照片保留为识别和对照证据，但默认不复制进交付文档。只有用户明确要求保留视觉证据时，才为每个对象保存一张忠实最终裁图；只允许非生成式旋转、透视、光照或对比度校正，禁止生成式修补和臆造线条。

始终分开四层：

- **逐字转录：** 只有印刷文字；
- **结构：** 中性的空间/关系编码；
- **关联说明：** 直接相关的印刷正文；
- **识别说明：** 不确定性与画面问题。

## 4. 呈现路由

选择信息损失最小的形式：

| 图表类型 | 默认呈现 |
|---|---|
| 简单表格、矩阵、对照网格 | 行连续的 Markdown 表格。 |
| 合并单元格或多级表头 | 跨行跨列确定时用 HTML 表格；否则嵌套转录。不得压平不确定层级。 |
| 统计图 | 围栏 SVG；有印刷精确值时再附数据表。 |
| 四象限、坐标、定位、时间轴 | 围栏 SVG + 结构化转录。 |
| 分层、放射、架构、概念拓扑 | 围栏 SVG + 节点/关系/层级转录。 |
| 流程、因果、路径图 | 优先围栏 SVG；仅当自动布局不改变形态时使用 Mermaid。 |
| 树、层级、分类 | 形态不重要时用缩进提纲，否则围栏 SVG。 |
| 公式或带注释方程 | 公式完整可读时使用 LaTeX + 逐字变量说明。 |
| 照片、广告、截图、复杂插图 | 图注、可读印刷文字、来源和中性对象转录，不强行重绘。 |
| 地图或不清晰复杂图 | 结构化转录；边界与标签清楚时才增加 SVG。 |

不得因为图中文字多就强制转表，也不得把照片臆造成结构图。

## 5. 提取流程

每个被选图表依次执行：

1. 记录选择原因：对象级物理标记，或持续生效的“全部图表”范围。
2. 确定对象边界与全部必要附属信息。
3. 识别页码并按锁定目录范围归章。
4. **先**转录印刷标签、数值、单位和来源，**再**还原几何。
5. 分类并套用呈现路由。
6. 对照核验行列归属、端点、箭头方向、分组、层级、图例映射、轴向和单位位置。
7. 只提取最少量直接关联说明并单独标注。
8. 图表标题和单独引用的关联说明末尾加页码上标。
9. 每个不确定字词、边界、关系或附属信息都写具体识别说明。
10. 通过下方三道质量门并运行 `scripts/validate_visual_markdown.py` 后再交付。

同页多个有独立编号的对象保持分开；真正共用图注或图例的对象合并为一个单元。跨页图表等待各部分到齐，或标记 `[图表截断，续页待补]`。

## 6. 保真与降级规则

保真优先级：印刷文字/数据/来源 → 明确关系 → 拓扑与相对位置 → 样式。

- 不从柱高、线位、面积、角度、颜色或地图明暗推断精确数值。
- 无标值曲线只描述可见相对变化。
- 不把邻近当因果，不补画看不到的箭头、节点、单元格、线条、标签或数据。
- 不根据相邻规律修正重复措辞、标点、大小写或缺失单元格。
- 不把阴影、透印、折痕或手写标记当成印刷编码。
- 使用 `[无法辨认]`、`[关系待确认]`、`[图表局部截断]` 等明确标记。
- 拓扑不确定时降级为结构化转录，不生成“看起来合理但实际错误”的 SVG。
- 源照片可用于校验还原，不等于允许把裁图复制进交付文档。

## 7. 三道质量门

### 内容门

- 每个被选对象都已出现，包括同页多个对象。
- 图注、标签、数值、单位、图例、来源和图表专属脚注齐全。
- 图形与结构化转录完全一致。
- 没有推断任何数值、关系或附属信息。

### 几何门

- 连接线在形状边界外留小间隙终止；除非原图如此，不能插入节点。
- 共边复用相同坐标。
- 平面分隔线由该平面派生并裁剪在平面内。
- 投影方向与深度偏移一致。
- 文字不与线条、图形或边框碰撞。
- 装饰性深度线与语义箭头能被区分。

### 渲染门

- Markdown 表格在 Obsidian、VS Code、Cursor 中正常成表。
- SVG 位于小写、不缩进的 `svg` 围栏中，不含外链图片或 Base64。
- 固定 `#F5F7FA` 画布、8% 黑色描边和明确深色前景，在 Obsidian 实时预览/阅读视图及应用明暗主题下均清晰。
- 已对照源照片核验标签、数据、关系和整体形态。

运行：

```bash
python3 scripts/validate_visual_markdown.py path/to/note.md --strict
```

脚本负责确定性的可移植性和带标签几何校验；跨编辑器渲染与源图对照仍须人工完成。
