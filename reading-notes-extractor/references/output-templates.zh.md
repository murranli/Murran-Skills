# 输出模板

生成完整/阶段性 Markdown 文件或图表语义单元前阅读本文件。

## 1. Unicode 页码上标

| 数字 | 上标 |
|---|---|
| 0 | ⁰ |
| 1 | ¹ |
| 2 | ² |
| 3 | ³ |
| 4 | ⁴ |
| 5 | ⁵ |
| 6 | ⁶ |
| 7 | ⁷ |
| 8 | ⁸ |
| 9 | ⁹ |

多位数依次拼接：第 8 页 → ` ⁸`；第 15 页 → ` ¹⁵`；第 153 页 → ` ¹⁵³`。

## 2. 单批次输出

只输出当前批次新增内容，按章节分组、页码升序。标注正文保持纯文本引用：

```markdown
### 章节名称

> 被标注原文。 ⁸

> 另一条被标注原文。 ¹⁵
```

## 3. 图表语义单元

使用四级标题。默认生成不含图片链接的单一 Markdown 文件。自包含 Markdown 在已核实的合并单元格确有需要时可包含行内 HTML 表格，但不得依赖同级资源文件。所有表格前后留空行，Markdown 表头、分隔行和数据行必须连续。

### 简单矩阵

```markdown
#### 图1-2　产品模型的检验矩阵 ⁷

结构化转录：

| 检验层次 | 维度一 | 维度二 | 维度三 |
|---|---|---|---|
| 是否能够 | 提高或不降低效率 | 降低或不提升成本 | 提升或不破坏体验 |
| 是否合理 | 提供的可能 | 发生的场景 | 接受的意愿 |
| 是否存在 | 市场 | 需求 | 用户 |

关联说明：

> 首先从最底层看要判断市场、需求，以及用户是否真正存在。 ⁷
```

Markdown 表格规则：

- 表头前与最后数据行后各留一个空行。
- 表头、分隔行与数据行之间不得插空行。
- 不得把表格放在引用块内。
- 单元格内的竖线写作 `\|`。
- 每行列数必须一致。
- 合并单元格结构不确定时，使用 HTML 或嵌套转录，不得压平。

### SVG 图或统计图（Obsidian SVG Editor）

````markdown
#### 图X-X　原图标题 ²⁴

```svg
<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 800 500" width="100%" role="img" aria-labelledby="fig-title fig-desc">
  <title id="fig-title">原图标题</title>
  <desc id="fig-desc">图中结构的简洁说明。</desc>
  <rect data-role="canvas-background" x="0" y="0" width="800" height="500" fill="#F5F7FA" fill-opacity="1" stroke="#000000" stroke-opacity="0.08" stroke-width="1"/>
  ...
</svg>
```

结构化转录：

- 节点：……
- 连接：……
- 层级/相对位置：……

关联说明：

> 与图表直接相关的原文。 ²⁴
````

填写 SVG 前阅读 `svg-reconstruction.zh.md`。`svg` 围栏不得缩进，也不得放入引用块、列表或 HTML 外壳。统计 SVG 只要有精确印刷数值，就必须追加紧凑数据表及坐标轴/图例转录。

### 纯文字降级

```markdown
#### 图X-X　原图标题 ²⁴

结构化转录：

- 可辨认对象：……
- 明确关系：……
- 〔关系待确认〕：……

识别说明：照片不足以可靠还原其余形态，因此未生成 SVG。
```

边界、合并单元格、端点或拓扑不确定时使用。克制的文字转录优于看起来合理但不正确的绘图。

只有图表后紧跟独立标注正文时才写“其他独立标注：”。一个句子同时属于独立标注与直接关联说明时，只放在“关联说明”中一次。

### 可选证据模式

只有用户明确要求保留视觉证据时，才在标题后加入真实保存的一张裁图：

```markdown
![图1-2 产品模型的检验矩阵](figures/p007-fig1-2.png)
```

不得输出占位或 Base64 图片。每个对象只保存一张最终裁图，使用稳定相对路径，且只做非生成式可读性校正。

## 4. 阶段性/完整 Markdown 文件

仅在用户要求完整笔记、阶段文件或合并文件时生成：

```markdown
# 《书名》读书笔记

> 作者：…｜原书名：…
> 说明：本笔记提取书中人工标注的原文与被选可视化对象，按原书目录归类，不做总结或改写。图表以结构化文字及必要的 SVG 围栏保留；建议在启用 SVG Editor 插件的 Obsidian 中阅读。每条信息或图表标题末尾的上标数字为页码。
>
> 提取进度：……（已提取至第 N 页）

---

## 第一部　部名（第37—152页）

### 1　章节名称（第37—52页）

_（待提取）_

### 2　章节名称（第53—62页）

> 已提取内容…… ⁵⁵
```

规则：

- 保留完整目录大纲与锁定页码范围。
- 正文和图表单元按页码嵌入所属章节。
- 未覆盖章节保留 `_（待提取）_`。
- 更新顶部进度。
- 默认一个自包含 `.md` 文件，不创建资源目录。
- 仅可选证据模式使用同级 `figures/` 目录和稳定相对链接。

## 5. 识别说明

仅在需要时附加：

```markdown
识别说明：
- 页码/章节归属不确定：……
- OCR 疑似：……
- 图表边界/关系不确定：……
- 图表画面问题（截断、阴影、虚焦、透视、遮挡）：……
- 待拼接文字/跨页图表：……
- 缺失图例/单位/来源/图注：……
- 采用文字降级而未生成 SVG：……
```

识别说明只陈述事实，不解释或发挥作者观点。
