# 模型库（Model Library）完整参考

## 市场与商业战略层

**核心问题**：不看产品长什么样，而是看竞品"在什么环境中，赚谁的钱，靠什么活下来"

| 模型 | 用途 | 适用场景 |
|-----|------|---------|
| **PESTEL 模型** | 宏观环境分析（政治/经济/社会/技术/环境/法律） | 进入新市场前的环境扫描 |
| **波特五力模型** | 行业与竞争格局分析 | 判断行业吸引力与进入壁垒 |
| **波特竞争战略** | 确定总体方向（成本领先/差异化/集中化） | 定位竞品整体战略方向 |
| **波特竞争战略轮盘** | 确保各项业务活动与核心战略高度对齐 | 检验战略一致性 |
| **安索夫成长矩阵** | 规划业务增长路径（市场渗透/市场开发/产品开发/多元化） | 分析竞品扩张逻辑 |
| **VRIO 分析** | 评估企业内部资源核心竞争力（价值/稀缺/难以模仿/组织） | 判断护城河深度 |
| **价值曲线（蓝海战略）** | 寻找与竞争对手差异化的价值空间，打破现有竞争格局 | 识别差异化机会 |
| **RIIF 战略模型** | 资源/信息/影响力/财务层面的战略构建 | 综合战略资源评估 |
| **行业生命周期理论** | 经济管理趋势演变判断 | 判断行业所处阶段 |
| **Gartner 技术成熟度曲线（Hype Cycle）** | 公众期望趋势演变判断 | 技术类产品时机研判 |
| **SWOT 分析** | 综合态势与市场定位 | 快速全貌扫描 |
| **商业模式画布（BMC）** | 梳理如何创造、传递和获取价值的九个核心模块 | 系统性商业模式解构 |
| **市场营销组合（4Ps/7Ps）** | 制定推向市场的具体营销策略 | 分析产品上市策略 |
| **知觉地图（Perceptual Mapping）** | 可视化消费者心中不同品牌/产品的定位坐标 | 品牌定位对比 |
| **基准比较法（Benchmarking）** | 对标行业最高标准，寻找战略差距 | 找到提升空间 |

## 产品与业务架构层

**核心问题**：关注产品"为了实现商业目的，提供了哪些解决方案"

| 模型 | 用途 | 适用场景 |
|-----|------|---------|
| **波士顿矩阵（BCG Matrix）** | 产品战略与优先级 | 多产品线资源分配分析 |
| **KANO 卡诺模型** | 产品特性与价值分层（必备/期望/魅力/无差异/反向） | 判断功能价值层次 |
| **利益相关者分析（Stakeholder Analysis）** | 生态中各方利益诉求与权力关系，寻找共赢点 | 平台类产品分析 |
| **vALUe** | 基于价值驱动的创新与评估框架 | 创新机会评估 |
| **MECE** | 将复杂业务挑战拆解为相互独立、完全穷尽的子问题 | 问题结构化拆解 |
| **Stage-Gate 模型** | 产品开发风险控制 | 产品研发阶段评估 |
| **哈里斯图表（Harris Profile）** | 多维度的概念优劣势直观对比工具 | 多方案横向比较 |
| **EVR 决策表** | 体验(Experience)/价值(Value)/风险(Risk) 维度的决策矩阵 | 功能决策评估 |
| **PMI（Plus, Minus, Interesting）** | 简单快速的概念利弊与启发点评估 | 快速方案评审 |
| **CBox（Creativity Box）** | 新颖度与可行性交叉评估矩阵 | 创新概念筛选 |
| **目标权重（Objective Weighting）** | 为多个业务目标分配权重，解决资源冲突 | 优先级排序 |
| **安索夫矩阵（Ansoff Matrix）** | 产品增长与扩张路径 | 产品线扩张分析 |
| **系统图（System Map）** | 俯瞰产品生态系统内各要素与角色的相互关系 | 生态系统分析 |
| **服务蓝图（Service Blueprint）** | 结合前台体验与后台支撑，定义端到端服务全链路与内部协作线 | 服务流程分析 |

## 用户体验与执行层

**核心问题**：关注用户在屏幕上"看到什么、点什么、感受到什么"，重点是"把事情做正确、做细致"

| 模型 | 用途 | 适用场景 |
|-----|------|---------|
| **Fogg 行为模型（B=MAP）** | 动机(M) + 能力(A) + 提示(P) → 行为转化 | 转化率与用户激活分析 |
| **用户旅程（User Journey）** | 串联微观触点，呈现完成特定任务的情绪与行为起伏 | 全链路体验分析 |
| **How Might We（HMW）** | 将痛点转化为具体的设计挑战和发散起点 | 设计机会识别 |
| **卡片分类法（Card Sorting）** | 验证信息展示分类是否符合用户真实心智模型 | 信息架构评估 |
| **古腾堡图表 & Z型/F型阅读流** | 分析界面排版是否顺应人眼自然扫视规律 | 界面布局分析 |
| **焦点流转评估** | 评估视觉注意力、交互控制权及任务上下文的直觉交接 | 交互流程评估 |
| **席克定律评估（Hick's Law）** | 分析可选数量是否增加了用户决策时间 | 选项设计评估 |
| **费茨定律评估（Fitts's Law）** | 评估可点击区域的大小及距离，判断操作便捷性 | 触控/点击设计评估 |
| **关键任务路径评估** | 拆解核心转化路径，分析每一步的流失概率及交互障碍 | 转化漏斗分析 |
| **原子设计理论（Atomic Design）** | 对界面基础构成元素进行系统化拆解，包含：排版与字体、色彩体系、空间规划与网格、视觉资产、Design Tokens映射、组件库扩展能力、设计原则一致性、视觉隐喻 | 设计系统深度拆解 |
