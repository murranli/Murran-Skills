# 旅行出行计划规划器 Trip Planner

把"想去某地玩几天"这种模糊想法，做成一份**可直接分享给同行人做决策**的出行计划：带信源、按可信度分级、结构清晰。

## 开工前必读（每次启动先做）

1. **先读校准日志** `references/calibration-log.md` —— 里面是过往真实教训（如"航班号不可伪装已核实"）。这些是硬约束，凌驾于本文其余部分。
2. **读准确性纪律** `references/accuracy-discipline.md` —— 信息分级与输出措辞规范，是本 skill 的立身之本。
3. 若有 auto-memory，读用户画像/偏好记忆，把已知偏好预填进第一阶段，减少提问。

## 边界

- **做**：意图厘清、多源调研、交叉验证、行程编排、按模板产出文档。
- **不做**：不替用户下单/付款；不伪造交易级数据（见准确性纪律）；不做已成行行程的记账；单纯"某地有什么好玩"的一问一答用普通检索即可，不必起本流程。

---

## 四阶段主流程

### 阶段一 · 意图确认（先对齐，再动手）

**目标**：把模糊诉求锁定成可执行的约束集。**先复述你的理解，再补问缺口**——不要一上来就问一长串。

必须落实的要素（缺哪个补哪个，已从记忆/上文得知的不要再问）：

| 要素 | 说明 |
|---|---|
| 出发地 / 目的地 | 决定交通、时长、签证 |
| 时间与天数 | 具体日期或"X月+N天"；是否涉及请假/拼假 |
| 同行人 | 人数、经验水平（如徒步新手）、特殊需求 |
| 核心体验 | 这趟"非做不可"的是什么（徒步？美食？出片？） |
| 花费取向 | 性价比 / 舒适 / 极致省；可"不预设，灵活组合" |
| 硬约束 | 天气痛点、体力、返程休息、必须避开的东西 |
| 输出与分享 | 给谁看、什么格式（默认 Markdown 可预览文档） |

**提问纪律**：只问真正影响方案骨架、且无法从常识/记忆推断的点。一次问 2–4 个，用结构化选项。能给推荐项就标"(推荐)"。
> 详见 `references/intake-checklist.md`。

阶段一产出：一段"我的理解"复述 + 一份确认过的约束集。**得到用户确认后再进入阶段二。**

---

### 阶段二 · 多路并行调研（分工，别串行）

按主题拆成**独立子调研**，用 Agent 工具并行跑（各自 general-purpose subagent），保护主上下文、缩短总时长。典型 5–7 路：

1. **政策与天气**：签证/免签、入境要求、目标月份气候（温度/降水/极端天气如台风），**这条常含"生死线"**（如免签的隐藏条件），主线可自己兼做。
2. **交通（去程/返程）**：航班/车次的**时段规律**、价格区间、直飞/中转、请假方案对比。→ 交易级信息按纪律处理。
3. **核心体验**：徒步路线/景点/活动的分级、时长、季节适配（如夏天要遮阳路线）、循序渐进编排。
4. **备选/填充活动**：应对天气或体力的 plan B（如正午高温的室内活动）。
5. **住宿**：分档（青旅/民宿/酒店），人均预估，选址策略（住哪最省交通）。
6. **餐饮**：特色 + 沿途便利 + 人均。
7.（可选）**装备/实用**：季节装备清单、当地交通卡、App、避坑。

**给子 agent 的 prompt 要点**：交代清楚背景约束（天气、新手、预算取向）、指定用 agent-reach 检索（小红书看真实场景 + Exa/网页看权威源，中英文关键词都搜）、**要求标注信源、要求遵守准确性分级、明确"查不到不要编造"**。
> 分工模板与 prompt 范式见 `references/research-playbook.md`。

---

### 阶段三 · 交叉验证与分级

汇总各路结果后，**不要照单全收**：

- **降级子 agent 的"已核实"措辞**：任何声称核实过的交易级数据（航班号、房源、实时价），主线要么亲自复核一次，要么在输出里降级为"参考值，须官网按日期核实"。宁可标注不确定，也不伪装确定。
- **交叉印证 A 类事实**：政策、气候、路线难度等尽量两个独立源一致再作为结论。
- **给每条信息定级** A/B/C（见准确性纪律），决定它在文档里怎么措辞。
- **识别生死线**：把"错了会导致行程崩盘"的点（签证隐藏条件、末班车、旺季售罄）拎到最前面。

---

### 阶段四 · 按模板分级输出

默认产出 **Markdown 可预览文档**（除非用户要 HTML）。用 `references/output-template.md` 的结构，逐块填充。要点：

- 开头放**生死线/关键提醒**（最影响决策的先说）。
- 交通/住宿用**表格对照**；行程用**逐日时段表**（时段｜安排｜备注），可用 emoji 标类型（🛬🏨🥣🌳🎨）。
- 提供**方案 A/B 对比**（如不同请假日期、不同预算档）。
- 交易级信息一律带"须核实"标注，附查证入口。
- 结尾列**信源**与**时效声明**。
- 涉及金额统一给汇率与"每人/整套"口径。

输出后：主动指出**哪些点需要用户自己去核实**、可继续细化的方向（如定了人数后精算人均）。

---

## 收尾 · 可持续校准（每次都做）

用户对本次产出给了纠正或验证后，**把可复用的教训写回** `references/calibration-log.md`（一条一条追加，带日期+根因+规则）。这是本 skill "越用越准"的机制。同时，若教训跨任务通用（不止旅行），也存一份到 auto-memory 的 feedback 类型。

## 可配置 / 通用化

本 skill 不硬编码任何个人信息。用户的默认出发地、审美偏好、预算取向等，**从 auto-memory 读取或在阶段一询问**，不写死在 skill 里。分享给他人使用时同样适用。
