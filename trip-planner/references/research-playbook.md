# 调研分工手册 Research Playbook

阶段二的执行细则：怎么拆、怎么并行、怎么给子 agent 下 prompt。

## 检索能力

优先用 **agent-reach** skill（`agent-reach doctor --json` 先体检后端）：
- **小红书**：中文真实场景、避坑、实测体验、民宿/美食口碑 —— 旅行调研的主力。
- **Exa / 网页(jina reader)**：权威源（官网、维基、政府政策）、英文侧交叉验证。注意 Exa 免费额度会限流(429)，被限流就改用 `curl -s "https://r.jina.ai/URL"` 读官网。
- **B站/YouTube**：路线实拍、vlog（需要动态感受时）。

## 并行分工（用 Agent 工具，general-purpose，后台并行）

按主题切成互不重叠的独立子调研，一次性并行发起。典型分工见 SKILL.md 阶段二的 7 类。**主线自己兼做"政策与天气"**（常含生死线，且不宜等）。

## 子 agent prompt 范式（每个都要包含）

1. **身份与背景**：一句话点明你是 XX 调研专家 + 完整约束（出发地、时间、同行人经验、天气痛点、预算取向）。子 agent 不知道上文，务必自包含。
2. **具体任务清单**：编号列出要查什么，每项要求返回哪些字段（价格标币种、距离标 km、时长标 h、难度分级…）。
3. **检索指令**：指定用 agent-reach，给出示例命令和建议的中英文关键词。
4. **准确性要求**（关键，照抄）：
   > 按可信度分级返回：权威慢变信息直接给结论+来源；有规律但需实时确认的给范围+"以实时为准"；**交易级/高时效信息（航班号、具体房源、实时价）给参考值也必须标注"须官网按日期核实"，绝不写"已核实/确认存在"。查不到就说查不到，不要编造。**
5. **输出要求**：中文结构化报告、字数上限、标注信源、不在 workspace 建文件（临时放 /tmp）。

## 汇总后（回到阶段三）

- 各路结果**交叉验证**，尤其对 C 类信息降级处理。
- 主线可对关键交易级数据亲自复核一次（如去航司官网 grep 一下航班号是否真在售）。
- 标记生死线，排序：最影响决策的放最前。

## 注意
- 不要主线和子 agent 查同一件事（浪费）。分工要正交。
- 子 agent 返回后，它的原始措辞不直接进最终文档——先过准确性纪律的"降级"关。
