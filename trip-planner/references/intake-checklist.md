# 意图确认清单 Intake Checklist

阶段一用。目标：**用最少的提问**把模糊诉求锁成可执行约束。先复述理解，再补问真正影响骨架的缺口。

## 要素清单（缺哪个补哪个）

- [ ] **出发地 / 目的地**
- [ ] **时间与天数**：具体日期 or "X月+N天"；是否请假/拼假（要不要做请假方案对比）
- [ ] **同行人**：人数、经验水平（如徒步新手→需循序渐进）、特殊需求（老人小孩、体力）
- [ ] **核心体验**：这趟非做不可的 1–2 件事
- [ ] **花费取向**：性价比 / 舒适 / 极致省 / "不预设，灵活组合"
- [ ] **硬约束**：天气痛点（怕热→遮阳/室内）、返程要留休息、必须避开的东西
- [ ] **输出与分享**：给谁看、什么格式（默认 Markdown 可预览）

## 提问纪律

1. **先复述**："我理解你要的是……"——把已知的（含记忆里的偏好）先摆出来，证明听懂了。
2. **只问骨架级缺口**：影响航班/预算/路线选择的才问；能从常识或记忆推断的不问。
3. **一次 2–4 个，结构化选项**：用 AskUserQuestion，每个选项给清楚的含义与取舍；有推荐项标"(推荐)"并放第一位。
4. **允许"不预设"**：花费/日期等用户常想灵活组合，给这个选项，别逼选。
5. 得到确认后再进入调研，不要边问边跑大调研。

## 常见可从记忆预填的偏好（示例，非硬编码）
- 默认出发城市
- 审美/内容偏好（如设计师重视觉、喜欢信息图式呈现）
- 一贯的预算取向
- 偏好的输出格式
> 这些应从 auto-memory 读，不写死在 skill 里。分享给他人用时，靠阶段一询问补齐。
