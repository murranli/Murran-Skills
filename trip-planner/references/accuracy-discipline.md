# 准确性纪律

本文件适用于出行调研、出行准备和详细行程三个阶段。目标不是让所有信息看起来确定，而是让用户清楚知道：什么是自己已经决定的，什么来自当前来源，什么只是规划估值，以及什么必须在行动前重新确认。

最严重的错误不是“没有查到”，而是把候选、估算、历史数据或间接推断包装成当前可执行的事实。

## 三维判断

不要再用单一 A/B/C 等级概括全部可信度。对会影响决策或执行的信息，同时判断事实状态、来源性质和操作风险。

### 1. 事实状态

| 状态 | 含义 | 使用方式 |
|---|---|---|
| **用户已确认** | 用户明确表示已经预订、决定或亲自核实 | 作为固定输入保留；不等于已核对当前运行状态 |
| **官方截至某日** | 当前官方来源在指定查询日期提供的信息 | 给结论、来源和查询日期；不暗示永久有效 |
| **规划估值** | 基于价格样本、典型耗时、历史气候或合理计算得到的范围 | 说明估算口径、依据和不确定性 |
| **出发前复核** | 高时效或一旦变化会影响执行的信息 | 说明复核时间、渠道和需要查看的字段 |
| **推断** | 由多个事实推导出的判断，而非来源直接陈述 | 明确写成建议或推断，并给出主要依据 |

这些状态可以组合。例如，用户已购航班同时属于“用户已确认”和“出发前复核”：航班号与预订时间是固定输入，但实际起飞状态、值机柜台和临时变更仍需复核。

只在状态会改变用户判断或行动时显示标签，不给每条常识性信息堆叠标记。

### 2. 来源性质

| 来源 | 适合支持 | 不应单独支持 |
|---|---|---|
| **官方一手来源** | 入境政策、运营规则、开放状态、时刻表、预警、票务条款 | 来源未覆盖的个体体验或未来保证 |
| **可靠二手来源** | 地图、地理关系、历史统计、跨平台比较、行业信息 | 高影响政策的最终结论、持续可售承诺 |
| **平台/聚合数据** | 价格快照、候选班次、房源供给和用户评分 | 当前一定可购买、官方规则或实际履约保证 |
| **社区与游记** | 体感、拥挤、踩坑、路线感受、服务体验 | 入境规则、路线开放、票务状态或安全结论 |
| **模型计算或推断** | 预算汇总、时间缓冲、方案取舍 | 伪装成来源直接给出的事实 |

一个准确匹配条件且仍有效的官方来源，通常优于多个转述它的二手来源。只有来源没有完整覆盖当前条件、不同官方页面冲突，或结论本身依赖真实体验时，才需要进一步交叉印证。

### 3. 操作风险

| 影响与时效 | 最低处理要求 |
|---|---|
| **高影响＋高时效** | 当前官方来源、查询时间、适用条件、复核节点；无法确认就明确缺口 |
| **高影响＋较稳定** | 官方或直接责任方来源、适用条件和有效日期 |
| **低影响＋高时效** | 给范围、代表性样本或查询方法，不追求虚假的精确值 |
| **低影响＋较稳定** | 用可靠来源简明支持，避免过度检索 |

入境资格、交通中断、路线关闭、极端天气、末班交通和固定预约通常属于高影响信息。餐饮口味、普通拍照点等不应消耗同等核查成本。

## 内部证据记录

对高影响结论保留以下最小记录，供输出审计使用：

- 结论或数值；
- 事实状态；
- 来源名称与链接；
- 来源发布/更新时间（能够取得时）；
- 实际查询日期；
- 适用的旅行日期、地点和用户条件；
- 是否存在冲突或推断；
- 建议复核时间。

这是一项内部质量控制，不要求把完整证据表暴露给用户。用户可见文档应把关键来源放在相关结论附近，并在文末汇总主要来源与查询时间。

## 分类规则

### 入境、政策与安全

- 先确认真正影响规则的条件，例如护照签发国家、入境地点、转机国家、旅行日期和停留方式。
- 优先使用政府、使领馆、移民部门、公共卫生或官方运营机构的当前页面。
- 不把搜索摘要、旧新闻、社区经验或“很多网站都这么说”当作最终依据。
- 政策即使长期未变，也必须写明查询日期。条件不完整或官方表述无法覆盖用户情况时，明确建议向责任机构确认。

### 航班、车次、住宿与门票

先区分候选信息和用户已确认信息：

- **候选信息**：可以写“截至 `<日期/时间>`，官方或平台查询显示该选项”，但不能写“已确认存在”“一定有票”或暗示稍后仍可购买。
- **用户已确认**：按用户提供的预订内容作为行程输入，标记“用户已确认”。除非用户请求核查或发现明显冲突，不擅自用检索结果替换。
- **运行状态**：航班是否延误、路线是否停运、房源是否变更、景点是否临时关闭，均在接近使用时间时复核。

航班雷达、历史时刻库、聚合票务页或搜索摘要只能用于发现候选，不能单独证明某日期当前在售。具体民宿名称若无法与标准房源稳定对应，改为区域、档位和筛选方法，不硬凑名称。

### 金额与汇率

- 标明币种、查询日期、单程/往返、每人/整套、每晚/全程，以及是否包含税费、行李或服务费。
- 实时价格使用带时间的快照；前期调研优先给范围，避免无意义的个位数精度。
- 汇率写明参考日期；预算汇总允许四舍五入，但要保持各项口径一致。
- 未查到、未计入或已包含的金额分别写清楚，禁止用 `0` 充当未知占位符。

### 天气与气候

- 只有旅行日期进入所用气象来源的有效预报范围后，才能称为天气预报，并标明来源、发布日期、地点和时区。
- 预报窗口外使用历史气候和季节风险，称为“气候参考”或“情景假设”，不能伪装成某日天气。
- 户外规划关注会改变行动的指标，例如降水、风力、体感温度、雷暴、能见度、海况或官方预警；不要只给晴雨图标。
- 详细行程中的 Plan A/B 应说明切换条件，并在临近出发时更新，不能把一次查询永久固化。

### 距离、耗时与转场

- 区分官方标称时长、地图计算时长、社区实测和规划缓冲，不混为一个“准确时间”。
- 写清当地时间、跨日、时区及起终点。阶段 3 的关键转场应核对营业时间、末班交通和缓冲。
- 由地图时间加上取行李、步行、等车或排队得到的结果属于推断，应说明主要组成，不伪装成运营方承诺。

### 社区内容与推荐

- 社区内容用于发现真实体验、常见问题和候选地点；优先观察多条内容是否反复出现同一模式。
- 区分体验事实与个人偏好。单个作者的“必去”“最好吃”只能支持推荐线索，不能升级为普遍结论。
- 广告、过度模板化内容、缺少时间地点或无法定位对象的内容降低权重。

## 冲突与缺失

- 来源冲突时，先检查发布时间、适用日期、适用人群、地点和定义是否不同，不直接按数量投票。
- 能解释冲突时给出适用边界；无法判断时并列呈现冲突，并说明用户应向哪个责任方核实。
- 没有证据时写“未查到”或“暂无法确认”，并给出下一步查询方法。缺失的诚实优于完整的虚构。
- 不继承工具、子任务或旧文档中的“已核实”措辞；进入最终输出前按本文件重新判断。

## 推荐措辞

| 场景 | 推荐表达 | 避免表达 |
|---|---|---|
| 用户提供已购机票 | “用户已确认：`<航班与时间>`” | “已通过网络验证该航班一定执飞” |
| 官方当前页面 | “截至 `<日期>`，`<官方机构>` 说明……” | “政策肯定不会变化” |
| 实时价格 | “`<查询时间>` 显示约 `<金额>`，以支付页为准” | “最终价格就是 `<金额>`” |
| 历史气候 | “历史上该时段通常……，用于情景规划” | “出行当天将会……” |
| 地图推算 | “地图基础时长约 X，另预留 Y 缓冲” | “全程准确需要 X 分钟” |
| 证据不足 | “当前未找到能覆盖该日期的官方信息” | 用相邻日期或历史记录填空 |

## 不同阶段的应用重点

- **阶段 1**：候选方案、价格范围和气候参考占比高。重点是说明取舍、估算口径和后续核实路径。
- **阶段 2**：政策、申报入口和截止日期占比高。重点是条件匹配、官方来源和行动期限。
- **阶段 3**：用户已确认输入与高时效运行信息并存。重点是保留固定决策、核对执行条件、设置天气与交通复核节点。
- **行后校准**：实际记录、主观体验和计划估值并存。重点是还原口径、区分可观察偏差与原因推断，并避免因最终顺利而弱化原有安全边界。

## 隐私与分享范围

- 私人准备清单可以保留完成申报或入住所需的地址、联系电话等操作信息。
- 面向同行人的分享版本只保留共同决策和执行所需信息。
- 公开案例或可复用模板必须移除护照信息、订单号、个人电话、可识别的私人联系方式及其他不必要的预订细节，并用清晰变量替代。

## 输出前检查

- 高影响结论有与当前条件匹配的来源和查询日期。
- 用户已确认输入、候选信息、估算和推断没有混写。
- 高时效信息说明了复核渠道或时间。
- 政策没有仅凭二手转述下结论，社区内容没有越权支持官方事实。
- 金额、时间、时区、人数和费用口径明确，没有用 `0` 或伪精确值掩盖未知。
- 来源冲突和证据缺口没有被静默删除。
- 分享或案例版本没有泄露不必要的个人与预订信息。
