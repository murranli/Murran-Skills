# 准确性纪律（本 skill 的立身之本）

信息不是都一样可信。**按可信度分级，决定怎么措辞。** 最严重的错误不是"没查到"，而是**把参考推测伪装成已核实的事实**——那会浪费同行人的核实成本、并摧毁对整份计划的信任。

## 三级分级

| 级别 | 特征 | 例子 | 输出方式 |
|---|---|---|---|
| **A 可信赖** | 权威源、变动慢 | 签证/免签政策、路线难度与距离、气候均值、景点开放性质、护照/文化惯例 | 直接给结论 + 标来源。尽量两个独立源印证。 |
| **B 方向性** | 有规律但需实时确认 | 航班/车次的**时段规律**、价格区间与旺淡季趋势、订票/订房平台建议、装备清单、人均预算档位 | 给范围与方法，显著标注"以实时为准"。 |
| **C 待实操** | 需交易级验证、高时效、易变 | **具体航班号/车次号、具体房源名、实时票价、库存与档期** | 给参考值**必须**紧跟"⚠ 须去官网按日期核实"，或干脆只给查证入口（官网/平台/关键词）。**永不写"已核实/已验证/确认存在"。** |

## 铁律

1. **C 类信息永不宣称已核实。** 即使子 agent 说"经 XX 核实真实存在"，也要降级——因为 Flightradar24 / flightsfrom / 聚合站会显示历史班次、包机、codeshare、季节性航班，"雷达上飞过"≠"当前航季官网在售"。真正的交易级核实只有航司/平台官网当日查询能做到，而那要用户自己下单时做。

2. **子 agent 的"已核实"措辞一律打折。** 主线复述前先降级；能亲自复核就复核（如去官网搜一次航班号），不能就明确标注不确定。

3. **查不到就说查不到。** 宁可写"该时段有 X 航司执飞，建议在 Y 平台按具体日期查询"，也不要编一个具体航班号填空。缺失的诚实 > 完整的虚假。

4. **给参考值也要给"怎么自己查"。** 每条 B/C 信息尽量附：去哪个官网/平台、用什么关键词、看什么字段。让用户能一步验证。

5. **金额永远标口径**：币种、汇率、"每人/整套"、是否含税/含行李。

## 一句话
> 用户会亲自去官网验证。假装确定的假信息，对会核实的人是负资产。**分级 + 标注核实路径**，是让这份计划可信、可用、可持续的底线。
